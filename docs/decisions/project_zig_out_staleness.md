**`zig build`을 부른 뒤에도 판정에 쓰이는 산출물이 직전 코드의 것일 수 있다.**
게이트 체인이 부팅하는 것은 `zig-out/bin/`의 바이너리이고, 호스트 검사는
`.zig-cache`의 실행 파일이다 — **둘 다 낡을 수 있고 증상이 다르다.**

## 증상이 양쪽으로 난다 — 그래서 여섯 번 보고도 매번 다른 것을 의심했다

| 편집 방향 | 어떻게 보이나 | 언제 봤나 |
|---|---|---|
| 코드를 **고쳤다**(깨뜨렸다) | **깨뜨렸는데 초록** | SC ×3, SM-M1 ×2 |
| 코드를 **되돌렸다** | **고쳤는데 빨강** | UT-M3 |

SC는 *"`zig build test`가 직전 내용의 결과를 낸다"*로 적었고 UT-M3은
*"`git checkout`으로 되돌려도 `zig-out`의 산출물이 안 따라온다"*로 적었다.
**`git checkout`도 `test`도 상관이 없다** — 같은 한 가지의 두 얼굴이다.

## SM-M1이 처음으로 비율을 쟀다

**절차:** 초록 상태를 한 번 빌드해 캐시에 넣고 → 씨앗에 `echo` 한 줄을 더해
**깨뜨리고** → 한 번만 돌려서 그것이 잡히는지 본다.

| 조건 | 첫 회차가 깨짐을 잡았나 |
|---|---|
| 따뜻한 캐시, `zig-out`도 그대로 | **5회 중 4회.** 1회는 **거짓 초록**이었다 |
| **`rm -rf init/.zig-cache init/zig-out`** | **4회 중 4회** |

거짓 초록이 난 회차는 `--summary all`에서 **run 스텝까지 `cached`**였다.
**다만 그 수로는 갈릴 수 없다** — 잡은 회차에도 `cached`가 같은 수로 찍힌
경우가 있었다. **"어느 회차를 믿을지 알려 주는 신호가 없다"**가 이 측정의
결론이고, 그래서 "두 번 돌린다"가 처방이 안 된다.

**`zig-out`만 지운 채 돌린 음성 확인 넷(체인 전체)은 넷 다 첫 회차부터
빨강이었다.** 그것을 원인의 증거로 읽지 않는다 — 거짓 초록이 5분의 1이므로
넷이 연속으로 옳게 나오는 것은 캐시를 안 지워도 절반쯤 일어난다.

## 범인이 아닌 것 — **다시 의심하지 말 것**

| 의심 | 어떻게 쟀나 | 결과 |
|---|---|---|
| **바인드 마운트**가 낡은 내용을 준다 | 호스트에서 파일을 고치고 컨테이너 둘에서 연달아 `cat` × 5회 | **아니다. 10/10 새 내용** |

그리고 **파일 크기가 바뀌는 편집에서도 일어난다** — SM-M1의 측정은 줄을 하나
**더하는** 편집이었다. "mtime만 바뀌어서 못 봤다"로는 설명되지 않는다.

**UT-M3은 실체를 직접 봤다** — 소스 mtime이 더 새것인데도 산출물이 옛것이었다.

```
zig-out/bin/init  3,360,856 bytes   ← 음성 확인용으로 빌드한 것이 그대로
rm -rf zig-out && zig build
zig-out/bin/init  3,363,824 bytes   ← 제대로 된 것
```

## 처방

**음성 확인을 하기 전에 둘을 지운다.**

```bash
rm -rf init/.zig-cache init/zig-out terminal/.zig-cache terminal/zig-out
```

**"두 번 돌린다"는 처방이 아니다.** 두 회차가 다른 답을 낼 때 어느 쪽이
참인지 말해 주는 것이 없고(위의 `cached` 수가 그 시도였다), 되돌리는 방향에서는
**두 번 다 거짓 빨강**일 수 있다. 저장소가 그 규칙으로 여섯 번을 넘겼고,
그동안 **음성 확인의 첫 회차를 세 번 잘못 읽었다.**

**루트 게이트(`check.sh`)는 이미 안전하다** — `clean()`이 매 판 시작에
`zig-out`과 `.zig-cache`를 **넷 다** 지운다(`check.sh:15`). 위험한 것은 체인을
**단독으로** 돌릴 때뿐이고, 음성 확인이 정확히 그 자리다.

## 함정의 입구 — 주석 한 줄

`check.sh:26`이 이렇게 적고 있다.

> Zig는 내용 해시로 판단해서 touch를 무시하므로 mtime 비교는 …

**그 문장은 게이트 진입 검사의 근거로는 옳다**(빌드를 부르는지만 본다). 그런데
그것을 읽은 사람이 **"그러니 산출물은 언제나 소스와 맞다"**로 확장하는 것이 이
함정의 입구다. 내용 해시가 그렇게 **동작해야 하는데 5분의 1은 안 그렇다**는
것이 위의 표다.
