사용자가 2026-09-11에 UT가 남긴 후보 넷 중 이것을 골랐다. UT design 실측
10이 `init/src/main.zig`의 한 줄을 인용하며 *"조건 없이 붙는다 — `zoxide`도
`fzf`도 걸 자리가 없다"*고 적고, 비목표 6이 **"셸 설정을 다루는
서브프로젝트가 생기면 그때 함께 온다"**고 남긴 그 문이다.

design은 `docs/superpowers/specs/2026-09-11-tars-shell-config-design.md`,
milestone 셋(SC-M0·M1·M2)이고 **SC-M0이 2026-09-11에 끝났다.**

관련: [[project_userland_tools]](결정 8이 `/config`에 사용자 파일을 두는
첫 선례를 만들었다) · [[project_config_persistence]](`tars.conf`의 파서는
PID 1 한 벌이다) · [[project_guest_environment]](`TERM`·`LANG`이 사는 자리를
`fish_greeting`이 셋째로 쓴다).

## 다시 조사하지 말 것 — 착수 전 프로브 (design 실측 14)

**저장소 코드를 한 글자도 안 고치고** 게스트 화면 셸에서 `fish`와 `zsh`를
맨손으로 띄운 것이 전부다. **위험 둘을 착수 전에 닫았고 결정 하나가
철회됐다.**

**1. fish는 인사말을 찍고, 빈 `fish_greeting` 환경 변수가 그것을 막는다.**

```
root@(none) ~# fish | Welcome to fish, the friendly interactive shell | ...
root@(none) ~# env fish_greeting= fish | root@(none) ~#
```

**그런데 이 인사말을 게이트가 마커로 쓰고 있다** — `machine/check.sh:117`이
UEFI 부팅의 판정으로 그 문구를 grep한다. 그래서 `/etc/fish/config.fish`로
시스템 전체를 끄면 **그 마커가 죽는다.** 처방은 `terminal`의
`setenv("fish_greeting", "", 1)` 한 줄이고 — **화면 셸만 조용해지고 시리얼
콘솔 셸은 지금처럼 찍는다.** `TERM`이 두 셸에서 갈리는 것과 같은 근거다.
**인사말을 건드리는 사람은 `machine/check.sh:117`을 함께 본다.**

**2. 프롬프트가 안 움직인다 — 이것이 이 서브프로젝트의 위험을 절반으로
줄였다.** 설정을 다 읽은 fish의 기본 프롬프트가 `--no-config`로 뜬 것과
**글자까지 같다**(`root@(none) ~#`). design 실측 9가 걱정한 게이트 좌표계
(`copy/check.sh`의 `col 20`)가 그대로 선다. **재기 전에는 추론이었다.**

**3. zsh의 newuser 마법사는 안 뜬다 — 결정 5가 철회됐다.** `/.zshrc`도
`/.zshenv`도 없는데 `-f` 없이 띄운 zsh가 곧바로 `(none)#`을 냈다.
sysroot에 `usr/share/zsh/functions/Newuser/zsh-newuser-install`이 있다는
사실로 세운 추론이었는데 **그것이 initrd에 안 들어갔다는 것을 안 봤다.**
UT-M3이 `pager`로 배운 것("sysroot에 있는 것과 initrd에 있는 것은 다르다")이
**반대 방향으로** 작동했다 — 그때는 없어서 죽었고 이번엔 없어서 살았다.
**`/.zshenv`를 만들지 말 것.**

**4. `sendkey`의 `shift-minus`가 게스트에 닿는다.** 밑줄이 제대로 쳐졌다.
UT-M3 실측 9가 *"이 저장소의 체인은 shift 조합을 쓴 적이 없다"*고만 적은
것에 대한 답이다 — **쓸 수 있다.** 다만 SC-M0의 게이트는 안 썼다(칠 것이
전부 소문자와 공백이다).

**5. `ps ax`가 셸의 argv를 화면에 보여 준다.** `tools/check.sh`가 이미 그
명령을 친다 — **부팅을 하나도 더 안 쓰고 플래그 변경을 화면에서 본다.**
이것을 안 찾았으면 SC-M0의 게이트는 정적 검사와 로그 한 줄뿐이었다.

## 사용자가 정한 것 — 다시 논의하지 말 것

| | 정한 것 | 안 고른 쪽 |
|---|---|---|
| 잇는 방법 | **링크 셋** — `/config` 아래 평평하게 | `HOME=/config`(프롬프트가 바뀐다) · 셸별 환경변수(bash가 구멍) |
| 설정 키 | `shell_config` **enum** `{on, off}`, 기본 `on` | `bool` · 기본 `off` |
| 왜 끌 수 있어야 하나 | **embedded 장비의 init 1으로 쓸 때** — 앱 하나가 도는 기계에서는 설정이 없는 쪽이 안전하다 | 언제나 켜기 |
| 씨앗 | **셋 다**, 프롬프트를 안 건드린다 | 현재 셸만 · 주석만 · 프롬프트를 우리가 정하기 |
| 탈출로 | **둘 다** — 감독자의 마지막 한 번 + `tars.noconfig` | 하나만 |
| 게이트 | **`config/check.sh`를 세 부팅으로** | 열두번째 체인 |

## `"none"` 토큰이 왜 필요한가

`on`일 때 `init`은 `terminal`에 **문자열 `"none"`**을 넘기고 terminal이 그
값을 보면 셸 argv에 아무것도 안 붙인다. 빈 문자열도 null도 아닌 이유는
**argv를 짓는 쪽(PID 1)과 쓰는 쪽(terminal)이 프로세스 경계로 갈려
있어서**다 — "인자가 없다"를 포인터로 못 보내고, 빈 문자열은 저쪽에서
"인자를 안 받았다"와 구분이 안 된다. **`Toggles.arg`가 빈 집합에 `none`을
쓰는 것과 글자 그대로 같은 이유다.**

**콘솔 셸은 이 토큰을 안 쓴다.** 그쪽은 init이 셸을 직접 exec하므로 argv를
짓는 쪽과 쓰는 쪽이 같다 — 슬롯을 null로 두면 그만이다. **`"none"`이
필요한 것은 화면 셸 하나뿐이다.**

## SC-M0이 실행으로 증명한 것

**1. fish는 `none`을 스크립트 파일 이름으로 읽는다.** terminal의 가로채기
한 줄을 지우면 `error: Error reading script file 'none'`이 뜨고 **대화형
셸이 아예 안 뜬다.** 그래서 죽는 것은 새 `ps ax` 검사가 아니라 그 앞의
검사 3(`ls`)이다 — **약속이 깨지면 조용한 오작동이 아니라 기계가 안
쓰인다**는 것이고, 위험의 모양으로는 이쪽이 낫다.

**2. 부정 검사가 불을 켜는 경우는 따로 만들어야 보인다.** Task 6이 긍정과
부정을 둘 다 넣었는데 plan의 되돌림 셋 중 **어느 것도 부정을 건드리지
못했다**(하나는 부팅 전에, 하나는 셸이 안 떠서, 하나는 호스트 검사가 먼저
죽는다). plan에 없던 네 번째를 만들어야 했다 — `init`의 `console_flag`를
조건 없이 `noConfigFlag()`로, 즉 **결정 4가 깨진 상태**로 두는 것이다.
그때만 긍정이 통과하고 부정이 죽는다. **검사를 넣었으면 그것이 죽는 경우를
직접 만들어 봐야 한다. 다른 검사가 먼저 죽으면 그 검사는 아직 아무것도
증명하지 않았다.**

**3. 기본값을 뒤집으면 부팅 전에 죽는다.** `Config`의 기본값을 `.off`로
바꾸면 `try expect("shell_config=on\n", .{})`가 먼저 반응해서
20초짜리 부팅 대신 10초짜리 호스트 검사가 답을 준다. **plan이 테스트를 Task
1로 앞세운 값이 두 번 나왔다** — tautology를 막은 것이 첫 번째이고 이것이
두 번째다.

**4. `expect()`를 안 넓히면 새 검사가 tautology다.** `config_test.zig`의 머리
주석이 HI-M2에 대해 이미 적어 둔 것이고, SC-M0이 그것을 여섯째 필드로
그대로 반복했다.

## **계획이 셋 깨졌고 셋 다 한 사실에서 나왔다 — 셸이 색을 쓰기 시작했다**

**`--no-config`로 뜬 fish는 구문 강조를 하나도 안 한다.** A/B로 쟀다: 같은
명령을 친 화면에서 플래그가 있을 때 row 0의 색 있는 셀이 **0개**, 없을 때
**32개**다. **프로브가 잰 것은 프롬프트의 글자였고, 바뀐 것은 색이었다** —
실측 14(c)가 "프롬프트가 안 움직인다"고 한 것은 참이었지만 그 문장이 덮는
범위가 생각보다 좁았다.

이 하나가 루트 게이트를 세 번 깼다. **셋 다 SC-M0이 만든 것이다.**

**1. `STYLE_DUMP_LIMIT`가 16이었다 — 명령줄이 예산을 먼저 다 쓴다.**
`render/check.sh`가 찾는 빨강 배경 셀은 **명령줄 아래 줄**에 있는데, 셀이
순서대로 덤프되므로 색칠된 명령줄 32칸이 예산을 다 쓰고 아래 줄이 통째로
잘린다. **진단 전체가 `terminal: style> 16 more cell(s) not shown` 한 줄
이었다** — 자르는 것을 조용히 하지 않기로 한 TR-M2의 선택이 세 milestone
뒤에 값을 냈다. 16 → **96**.

**2. 줄을 넓히는 것은 앞과 뒤를 동시에 건드린다.** plan은 *"다른 체인들이
`tars-init: config shell=`을 **앞부분**으로 grep하므로 앞이 안 바뀌어야
한다"*까지만 적었는데, `hangul/check.sh:304`가 **`$`로 뒤에 매달려
있었다.** 처방은 끝 대신 **경계**(`( |$)`)를 보는 것이고, `$`를 썼던
이유(짧은 목록이 긴 목록의 접두사로 맞는 것을 막는다)는 그대로 산다.
**저장소에서 그 줄을 grep하는 자리 열둘 중 끝에 매달린 것은 이 하나뿐
이었다.**

**3. "반전됐다"를 색 두 개로 박아 두면 셸이 색을 쓰는 순간 틀린다.**

```
FAIL: the cursor on a committed 가 took 0 inverted cell(s), expected 2
terminal: style> 0,15 fg=102030 bg=D54E53
terminal: style> 0,16 fg=102030 bg=D54E53
```

**커서는 두 칸을 제대로 덮고 있었다.** `D54E53`은 fish가 모르는 명령에 쓰는
빨강이고, 검사는 `fg=102030 bg=FFFFFF`를 세고 있었다 — 그 표기는 "반전됐다"가
아니라 **"반전됐고 그 글자의 전경색이 기본값이다"**를 뜻한다.
**반전의 표식은 `fg`가 기본 배경색이라는 것 하나이고, `bg`는 그 글자가 원래
갖고 있던 색이라 검사가 알 바가 아니다.** 같은 가정을 쓰는 자리가
셋(`hangul`·`copy`·`render`)이었고 깨진 것은 하나였지만 **셋 다 고쳤다** —
나머지 둘은 이번에 마침 커서가 색 없는 글자 위에 섰을 뿐이다.

**`copy/check.sh`의 앰버 하이라이트 계수 셋(`fg=FFFFFF bg=C08000`)은 안
고쳤다** — 같은 종류의 가정이지만 그쪽은 우리가 칠하는 색이고 깨진 증거가
없다. **알고 두는 부채다.**

**이 셋을 한 문장으로:** *게이트가 화면의 색을 판정에 쓰는 자리는 전부
"셸이 색을 안 쓴다"를 조용히 전제하고 있었다.* 그 전제가 어디에 몇 개나
있는지는 `--no-config`를 떼기 전에는 아무도 셀 수 없었다.

UT-M3의 23분 43.15초에서 **+25.64초**(잡음 ±3분 안). **두 번째 회차다** —

## SC-M0이 게이트로 **못 보는 것** — SC-M1·M2가 열려 있다

| 못 보는 것 | 왜 |
|---|---|
| rc가 **실제로 읽히는가** | 파일이 아직 없다. SC-M1의 일이다 |
| `off`가 rc를 **막는가** | 같은 이유. SC-M1의 3차 부팅이 부정 검사로 본다 |
| 링크가 가리키는 **대상** | `tools/check.sh`에 디스크가 없어 `/config`가 빈 디렉터리다. 링크의 **존재**까지만 본다 |
| 인사말이 화면에 없다 | **어느 체인도 이것을 판정으로 안 갖는다.** 사람이 `grep -a "terminal: screen>" | grep -c "Welcome to fish"`로 한 번 보는 것이 전부다 |

## 아직 열려 있는 위험 — rc가 깨지면 그것을 고칠 셸이 없다

CP가 `tars.conf`에 대해 만든 세 장치(화이트리스트 · 모르는 값 무시 · 읽기
실패 시 덮어쓰지 않기)는 **rc에는 안 통한다.** rc는 우리가 파싱하는 것이
아니라 셸에게 통째로 넘기는 코드다. 결정 8·9(감독자의 마지막 한 번 ·
`tars.noconfig`)가 답이고 **SC-M2까지 이 위험이 열려 있다** — 그때까지
탈출로는 호스트에서 ext2 이미지를 직접 고치는 것뿐이다. **M1의 씨앗이
무해해야 하는 이유가 여기에 있다.**
