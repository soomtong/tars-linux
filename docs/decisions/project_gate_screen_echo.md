# 게이트의 화면 판정은 자기가 친 명령도 화면으로 센다

NW-M3(2026-09-14)에서 검사 하나를 쓰다가 드러난 성질이다. 이 저장소의 체인
여덟이 같은 방식으로 판정하고 있어서 전부에 해당한다.

## 무엇이 문제인가

`gate_lib.sh`의 `wait_for_screen`은 로그에서 `terminal: screen>` 줄을 전부
모아 패턴을 건다. 마지막 프레임이 아니라 부팅 이후 찍힌 모든 프레임이다.

게스트에 친 명령은 셸이 에코해서 화면에 나타난다. 그러니까 명령줄 자체가
판정 대상 안에 있다 — 패턴이 명령줄 안의 글자면, 그 명령이 아무 일도 안 해도
검사가 초록이 된다.

```bash
# 이렇게 쓰면 dhcpcd가 죽어 있어도 통과한다
type_keys p g r e p spc minus l spc d h c p c d ret
wait_for_screen "dhcpcd"        # 친 명령의 에코가 이미 dhcpcd다
```

증상이 조용하다는 것이 이 함정의 성질이다. 검사는 늘 초록이고, 그것이
"기능이 산다"인지 "검사가 자기를 본다"인지가 화면에서 안 갈린다.

## 처방 — 출력에만 생기는 글자를 만든다

명령 치환으로 값을 만들어 붙이면 명령줄과 출력의 글자가 갈린다.

```bash
# echo dhcpcd-alive=$(pgrep -c dhcpcd)
#   명령줄:  dhcpcd-alive=$(pgrep -c dhcpcd)
#   출력:    dhcpcd-alive=1
type_keys e c h o spc d h c p c d minus a l i v e equal \
  shift-4 shift-9 p g r e p spc minus c spc d h c p c d shift-0 ret
wait_for_screen "dhcpcd-alive=[1-9]"
```

`$(`가 `shift-4 shift-9`, `)`가 `shift-0`이다. fish가 `$(...)`를 읽는다는
것은 `config/check.sh`의 `NEG_COUNT_KEYS`가 이미 증명했다.

다른 길도 있다. 판정 글자를 우리가 바깥에서 넣는 것이다 — `net/check.sh`의
검사 9가 그 모양이다. QEMU가 `guestfwd`로 흘려 넣는 `nwm3-outbound-ok`는
게스트가 실제로 연결을 열었을 때만 화면에 생기고, 명령줄(`nc -w 5
10.0.2.100 8080`)에는 그 글자가 없다.

## 검사를 쓸 때 물어볼 것

1. 이 패턴이 내가 친 명령줄 안에 있나. 있으면 그 검사는 늘 초록이다.
2. 없다면, 그 글자를 만들 수 있는 것이 실행 결과뿐인가.

둘째가 중요하다. 명령줄에 없어도 그 화면 어딘가에 이미 있는 글자면 같은
문제다 — 프롬프트, 앞선 명령의 출력, 배너가 전부 화면이다.

## 확장판 — 치지도 않은 글자가 화면에 남는다 (fish)

IN-M2(2026-09-14)가 찾았다. 위의 이야기는 "우리가 친 명령의 에코도 화면
이다"인데, fish에서는 치지 않은 글자도 화면에 남는다.

fish는 타이핑 중에 히스토리에서 이어질 만한 꼬리를 회색으로 제안한다.
그 제안이 붙은 줄이 무언가에 밀려 스크롤되면 화면에 그대로 남는다.
`net/check.sh`의 검사 14가 `nc `까지 쳤을 때 이 줄이 화면에 생겼다.

```
root@(none) ~# nc -w 5 10.0.2.100 8080
fish: Job 1, 'echo inm1-inbound-ok | nc -l -p…' has ended
```

`nc -w 5 10.0.2.100 8080`은 같은 부팅의 검사 9가 친 명령이고 검사 14는
그것을 치지 않았다. 즉 위의 "검사를 쓸 때 물어볼 것" 둘째(그 화면 어딘가에
이미 있는 글자인가)에 후보가 하나 는다 — 같은 부팅에서 앞서 친 명령의
꼬리가, 그 접두사를 다시 치는 순간 나타날 수 있다.

처방은 바뀌지 않는다. 판정 글자를 출력에만 생기게 만들면 제안에도 안 나온다
(제안은 명령줄의 재방문이지 출력의 재방문이 아니다). 그리고 milestone마다
판정 글자의 접두사를 다르게 두는 관습(IN 결정 8, BB-M2가 배운 것)이 이
자리에서 한 번 더 값을 한다.

## 그 로그를 사람이 읽을 때 — 행 구분자가 `|`다

판정이 아니라 진단 이야기다. `terminal: screen>` 줄은 화면의 행을 ` | `로
이어 붙여 한 줄로 만든다. 그래서 로그를 읽을 때 `tr '|' '\n'`으로 행을
복원하는 것이 이 저장소의 관습인데, 화면에 `|` 문자를 찍는 명령을 치면 그
문자와 행 경계가 구별되지 않는다.

IN-M1(2026-09-14)이 그런 명령을 치는 첫 자리다. `echo inm1-inbound-ok | nc -l
-p 8080 &`를 친 회차에서 복원된 화면이 이렇게 보였다.

```
 root@(none) ~# echo inm1-inbound-ok
 nc -l -p 8080 &
```

한 줄인 명령이 두 줄로 갈려서 잠깐 "파이프가 안 들어갔나"로 읽힌다. 실제로는
들어갔다 — 확인하려면 쪼개지 말고 원본 줄을 그대로 보면 된다.

```bash
grep -a "terminal: screen>" serial.clean | tail -1
```

## 게스트에 심는 배경 job은 stdin을 끊어 준다

TS-M2(2026-09-15)가 찾았다. 이것은 판정 글자의 이야기가 아니라 게스트에 치는
명령이 회차마다 다르게 동작하는 이야기이고, 증상이 "길이 안 섰다"와 똑같아서
원인에서 멀다.

`net/check.sh`의 검사 14가 이렇게 쳤다.

```
nc -l -p 8081 > /tmp/inm2.txt &
```

이 job이 열일곱 판 중 두 판에서 받은 바이트를 파일에 안 썼다. 화면을
복원하니 한 글자가 답이었다.

```
root@(none) ~# cfish: Job 1, 'nc -l -p 8081 > /tmp/inm2.txt &' has stopped
```

`ended`가 아니라 `stopped`다. 배경 job의 stdin이 터미널인데 `nc`는 연결이
오면 stdin도 읽으려 하고, 배경에서 터미널을 읽으면 커널이 SIGTTIN을 보내 그
job을 멈춘다. 멈춘 프로세스는 아무것도 안 쓴다.

같은 부팅의 8080 리스너가 이 병에 안 걸린 이유가 처방을 알려 준다 — 그쪽은
`echo … | nc -l -p 8080 &`이라 stdin이 파이프이고 터미널이 아니다. 그래서
처방이 `< /dev/null` 한 조각이다.

```
nc -l -p 8081 < /dev/null > /tmp/inm2.txt &
```

물어볼 것이 하나 는다 — 게스트에 배경으로 심는 명령이 stdin을 읽을 수 있나.
읽을 수 있으면 끊어 준다. 그리고 화면에서 `has stopped`를 보면 그것이 이
병의 이름이다.

## 드라이버 이름이 숫자면 타임스탬프에 걸린다

같은 날 같은 체인에서 나온 둘째다. 검사 11이 켜지 않은 NIC 드라이버 이름을
시리얼 로그에서 찾는데 그 목록에 `8139`가 있었고, 커널 printk의 타임스탬프가
그 숫자를 품는다.

```
[    1.381391] clocksource: tsc: mask: 0xffffffffffffffff ...
```

부팅 시각이 그 값일 때만 빨간불이 되므로 흔들린다. 고친 방법은 커널이 실제로
찍는 모듈 이름 둘(`8139cp` · `8139too`)로 바꾼 것이다. `\b`를 붙이는 길은 안
골랐다 — 소수점 바로 뒤(`[    2.813900]`)에서는 그 경계가 서기 때문에 함정이
좁아질 뿐 안 없어진다.

규칙으로 적으면 이렇다. 로그에서 이름을 찾는 검사는 그 이름이 숫자만으로 될
수 없는지 먼저 본다. 이 저장소의 시리얼 로그에는 타임스탬프와 좌표와 색이
수백만 자 들어 있고, 그 안에서 짧은 숫자는 언젠가 반드시 나타난다.

## 관련된 다른 자리

같은 병이 화면이 아닌 곳에서도 나온다. SD 실측 11이 그것인데, 그쪽은 게스트
히스토리 파일이다 — `grep`의 명령줄이 실행 전에 히스토리 파일에 써져서
패턴이 자기를 세고, 음성 기대값이 0이 아니라 1이 된다. 처방도 같은 종류다
(`grep -x`로 줄 전체 일치를 요구한다).

즉 규칙은 "판정 대상에 우리가 친 명령이 들어가는가"를 먼저 묻는 것이고,
화면이든 파일이든 답이 같다.
